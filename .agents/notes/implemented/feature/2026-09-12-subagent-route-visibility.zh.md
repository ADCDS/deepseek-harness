# Agent Note: 子代理路由可见性

Status: implemented

[English](2026-09-12-subagent-route-visibility.md) | 中文

## Problem

阅读会话的人无法判断哪个提供方和模型服务了某个子代理。三个界面都没有给出它：标题栏目录行只报告模式、活动状态、token 与耗时；委派工具卡片只报告调用描述；而打开子会话根本不渲染模型座位，因为对于选择不可用的会话，`ModelSelect` 返回空。启用按次模型选择的部署、携带 `agentRouteDefaults` 的提供方，以及进程外后端，都可能让子代理运行在与父代理不同的路由上，所以“与父代理相同”从来不是安全的假设。

## Decision

路由本就持久存在：`request/header` 记录每次请求确切的 `provider`/`model`，而 `modelSelection` 投影按会话折叠它，子会话同样如此。报告它是基于该投影的展示变更，外加一项工具自有的结果事实；不需要新的会话事件，也不需要描述符版本变更。

[子代理目录](../../../../packages/client/ui-subagent/README.zh.md)从子会话自身的摘要投影中读取 `modelSelection.lastUsed`，与该行已消费的 `tokenUsage` 和 `subagentTiming` 并列，并让 `provider/model` 独占一行，位于 label 行与 title、mode、活动状态行之间。共用一条会被截断的行，会把路由挤到 LLM 撰写的标题之后，而该标题恰恰是路由要用来区分同级子代理的值。

[模型座位](../../../../packages/client/ui-model-selection/README.zh.md)把子代理的固定路由报告为禁用触发器，而不再什么都不渲染。读取咨询性目录现在对每个会话开放，因为它是 Host 代次范围的展示数据，不指名任何会话；`select` 保留会话权限，仍然拒绝。该座位在模型旁边点明提供方，这是可选择座位不做的：平台恰恰是子会话读者缺失的事实。

[只读编辑器](../../../../packages/client/ui-subagent/README.zh.md)报告同一路由。该接管会替换常驻编辑器，并连带替换 `conversation.input.model` 模型位，因此一次性 child 或父会话离线的 child 本来在其自身页面上任何位置都看不到路由，而该页面的 title 是可能取名任意的模型撰写文本。它经由会话作用域的 `useProjection` 钩子读取路由，而非该座位的服务，因为这两个界面各自通过自身插槽作用域所提供的通道抵达该投影。

[委派工具](../../../../packages/subagent/tool-subagent/README.zh.md)在其规范输出中携带生效的子代理路由，并通过 `presentationMeta` 投影它，于是[工具行](../../../../packages/client/ui-tool/README.zh.md)把 `provider/model` 追加到已结算委派的摘要上。`render` 忽略该字段，因此没有任何已渲染的结果文本发生变化；`presentationMeta` 对参数与值是纯函数，而只有模型显式选择路由时参数才携带它，因此继承的路由只能经由规范值抵达展示层。在 PTC 模式下，该值的 schema 属于 `ToolOutputMap` 前缀，每个结果分支增加一个可选 `route` 对象，并一次性使已缓存的前缀失效。

## Alternatives considered

**扩展持久的子代理描述符**，像可继续子代理那样为一次性子代理记录 `agentProvider`/`agentModel`，会为了取得 `request/header` 已为每个子代理携带的事实而给持久记录升版本。描述符报告的还是**请求的**路由，在会话中途切换后会与**实际使用的**路由分歧。

**从子会话摘要推导工具卡片的路由**可以省去工具自有的输出字段，但会把父转录中一条已结算的行绑定到子会话投影的继续存在上，并且在子代理首次请求落地前，后台委派的行会是空的。

**仅从投影渲染子代理座位**、跳过目录，可以避免放宽 `load`，但也会丢失每条路由的提供方与模型显示名，在父座位打印目录名的地方打印原始 id。

## Consequences

路由只在子代理首次请求记录了 header 之后才出现；在此之前目录行省略该行、两个子会话界面均不渲染，与该座位既有的空白窗口一致。目录未登载的路由以其原始 id 命名，因此未登载或已撤下的模型仍然可读。目录行与只读框始终打印原始 id，因为二者都无法访问模型目录，而子代理座位打印显示名；弥合这一差距需要服务或插槽，而非跨插件导入。

`delegationRoute` 校验持久化的 `meta`，因为该值是工具自有的持久 JSON，可能由另一个构建写入。本次变更之前记录的委派没有结果元数据，那些行保留原有摘要。

聚焦测试覆盖目录的两个分支、路由独占一行、座位的固定/空白/未登载路由三种渲染、只读框在有路由与无路由两种情况下的渲染、放宽后的目录加载与仍被拒绝的选择、覆盖与纯继承两种情况的路由元数据、无任何层提供完整路由时元数据的缺席，以及该行对畸形元数据的拒绝。

[模型选择的子代理路由](2026-08-18-model-selected-subagent-routes.zh.md)拥有子代理**可以**运行哪条路由并保持权威；本记录只拥有报告已解析的那一条。按次选择仍为可选开关且默认关闭（`subagent-model-selection`），因此默认部署会显示每个子代理都在父代理的路由上。该默认值是否应当改变是另一个问题，本记录不作决定。
